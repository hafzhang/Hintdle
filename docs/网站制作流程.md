# hintdle 网站制作流程

> 目标：做一个 Poople 词梯（Word Ladder）的**提示与答案工具站**，核心产品是分级提示（hint），答案页是副产品。
> 品牌：**hintdle**（hint + dle），主域 hintdle.com；产品定位与市场依据见《[hintdle产品方案](hintdle产品方案.md)》。
> 本文档是从 0 到上线的完整执行流程，数据层（阶段一）与每日题目获取（阶段二）已在本仓库落地并通过基准验证。

---

## ⭐ 重大发现（2026-11-22，逆向官方 bundle 验证）

对 poople.io 前端 JS bundle（`/assets/index-*.js`，普通 HTTP 可下载）逆向后确认：

1. **官方可玩词图 = 2,398 个四字母词**（变量 `xE`），内嵌于 bundle。在该词集上用自有 BFS 复算距离，与官方内嵌距离 **2,398/2,398 完全一致**。
2. **全部 1,137 期题目序列内嵌于 bundle**（变量 `FE`，PICK #0 → HAIL #1136，够用到 2028-09），每日起始词 = `FE[题号]`，**确定性计算，无需无头浏览器**。
3. **换题时间 = 每天 08:00 UTC（北京 16:00）**，锚点 2025-08-15 08:00 UTC（前端函数 `Zt()` 复现已验证）。
4. **浏览器实测基准：2026-11-22 poople.io 显示 `#464: JUGS`**，与 bundle 解析一致。
5. **poople.org（第 1 名竞品）与官方游戏不同步**：它自称 Independent，其「#464 TAXI / 5,395 词图」是它自己的独立游戏数据，**不是官方数据**。官方 #464 = JUGS，TAXI 要到 #866 才出现。这是我们的差异化机会：做真正对齐官方 poople.io 的答案站。
6. bundle 还内嵌一张词频表（变量 `D0`，2,749 词），已随数据层一并提取备用。

**结论：阶段二原计划的「Playwright 无头浏览器」方案作废**，改为「普通 HTTP 下载 bundle + 本地解析」，更稳定、可降级、零 JS 执行依赖。

## 0. 定位与红线

### 做什么
- 用**官方 bundle 内嵌数据 + 自有 BFS 算法**生产词梯数据，题号/起始词/步数与官方 100% 一致（竞品 poople.org 做不到）。
- 产品形态：**一屏式答案 + 四层 spoiler-safe 分级提示 + 任意起始词求解工具**；首屏 ≤1 秒可见答案，停留时间目标 >60 秒（竞品 12–28 秒）。
- 8 个核心页 + 约 2,397 个 `/from/{word}/` 长尾页，吃答案词、工具词和长尾词流量。

### 明确不做（四条红线）
1. **不碰品牌词**：域名、站名、页面标题不出现 poople / krillion——商标投诉一来，站和域名一起丢。
2. **不爬** poople.org / poopleanswer.com 的答案页——竞品内容且每天变，抄来就是错数据。
3. **不抄**任何站点的英文原文——重复内容没有排名。
4. **不做可玩复刻版**——官方 unlimited 是 1,476 道题的版权题库，不抓不复刻；只做规则说明 + 答案、提示、工具。

### 参考对象（只学结构，不抓内容）
| 对象 | 学什么 |
|---|---|
| poople.io（官方站） | **数据唯一来源**：下载其 JS bundle 解析词图与题目序列（每日管线）；页面本体不参考 |
| poople.org（第 1 名竞品） | 页面结构、四层提示设计；其题号与官方错位是我们的差异化锚点 |
| stuckonaword.com（老工具站） | 通配桶 + BFS 算法、三种结构化数据、Data & Methodology 页写法 |
| wordzingo.com（长文范本） | 单页 6,000+ 字符的原创长文结构（起源/规则/技巧/FAQ） |

## 2. 阶段一：数据层（已落地，切换至官方图）

### 2.1 数据源

**唯一事实源：官方 bundle 内嵌数据**（缓存 `data/raw/poople_bundle.js`）：

| 内嵌数据 | 前端变量 | 规模 | 用途 |
|---|---|---|---|
| 官方可玩词图（词 + 到 POOP 距离） | `xE` | 2,398 词 | 全站数据源，自有 BFS 复算 100% 吻合 |
| 每日题目序列（词 + 距离） | `FE` | 1,137 期 | 答案存档 / 每日页 |
| 官方词频表 | `D0` | 2,749 词 | 词频排序展示 |

公开词表（SOWPODS / ENABLE / dwyl / Google 万词，`data/raw/*.txt`）保留作交叉验证与后续扩展用。旧管线 `build_word_graph.py` 曾用 SOWPODS 复现 poople.org 声称的 5,395 词图——**该基准后被证明属于竞品自己的独立游戏，与官方无关**，现仅作方法论参考。

### 2.2 验证链（全部通过）

1. 自有 BFS（通配桶建图 + 从 POOP 求解）在官方 2,398 词集上复算距离 = bundle 内嵌距离：**2,398/2,398**。
2. 题目序列距离复算：**1,137/1,137**。
3. 浏览器实测 poople.io 头部 `#464: JUGS` = bundle 解析结果（2026-11-22）。
4. 官方距离极值：最远 11 步（UMPH / INCH / AUGH）；POOP 一步邻居 11 个。

### 2.3 数据产物（`data/processed/`）

| 文件 | 内容 | 消费页面 |
|---|---|---|
| `word_ladder_4letter.csv` | 每词：距离、前驱、最短路径数、可达、官方词频 | 全站数据源 |
| `poop_neighbors.json` | 一步到 POOP 的词（11 个） | `/word-ladder-patterns/` |
| `daily_sequence.csv` | 全部 1,137 期：题号、词、距离、生效 UTC 窗口 | 答案存档页 |
| `graph_stats.json` | 距离分布、极值词、基准验证结果 | `/word-ladder-statistics/`、Data & Methodology |

复现命令：

```powershell
python scripts/build_official_graph.py            # 从缓存 bundle 重建全部数据（含验证断言）
python scripts/build_official_graph.py --refresh  # 强制重新下载 bundle
python scripts/hint_engine.py jugs                # 任意词的四层提示
```

## 3. 阶段二：每日题目获取（已完成，无需无头浏览器）

### 3.1 方案（替代原 Playwright 方案）

`scripts/fetch_today.py` 每日运行：

1. 普通 HTTP 下载 poople.io 首页 → 定位当前 `/assets/index-*.js` → 下载 bundle（浏览器 UA + 3 次重试）。
2. 复现前端 `Zt()` 计算当日题号；起始词 = `FE[题号]`（确定性）。
3. 双重校验：起始词必须在 2,398 词图内，且本地 BFS 距离 = bundle 序列距离，不一致即失败。
4. 生成当日 JSON：`data/daily/YYYY-MM-DD.json`（日期 = 题目生效的 UTC 日），含四层提示、揭示路径、全部等长最短路径。

### 3.2 调度与降级（已注册）

- 定时任务已注册（Schedule ID `10c9aeb6`）：**每天北京时间 16:10** 执行 fetch_today.py，成功时汇报题号/起始词/步数，失败时读 `data/daily/alerts.log` 并报告。
- 降级铁律：**任一环节失败不写任何数据**，只追加告警日志；昨日归档保持可访问。错数据比不更新更伤。
- 题目序列内嵌至 #1136（2028-09 用尽），届时官方会发新 bundle；每日重新下载天然感知改版（bundle 路径带 hash）。
- 已演练：网络异常 → `[ALERT]` + 非零退出码，无错误数据落盘（2026-11-22 实测）。

### 3.3 验收

- [x] bundle 解析 + 本地 BFS = 官方内嵌距离（2,398/2,398 词、1,137/1,137 期）
- [x] 浏览器实测 #464 JUGS 与解析一致
- [x] 失败时不写数据、有告警日志
- [x] 定时任务注册（16:10 Asia/Shanghai）
- [ ] 连续 7 天稳定运行观察（进行中）

## 4. 提示引擎（核心产品，已就绪，属阶段一交付物）

四层提示由弱到强，与竞品验证过的设计一致（`scripts/hint_engine.py`，示例为官方 #464 JUGS）：

| 层级 | 内容 | JUGS 示例（#464 实测） |
|---|---|---|
| Hint 1 | 最优路径共几步 | 最短 5 步 |
| Hint 2 | 第一步改动第几位 | 第 1 位（J） |
| Hint 3 | 该位字母变化 | J → B |
| Hint 4 | 第一步完整单词 | JUGS → BUGS |
| 揭晓 | 完整最短路径 + 等长路径数 | 3 条，默认展示 1 条（JUGS→BUGS→BOGS→BOOS→BOOP→POOP） |

交互要求：每层提示默认折叠、点击逐级展开，URL 带 `#hint-2` 锚点且不剧透下层内容；答案区与提示区物理分离。

## 5. 阶段三：页面工程（核心八页 + 长尾矩阵）

对齐《hintdle产品方案》§3：8 个核心页 + 约 2,397 个长尾页，构建期全部静态生成（M4/M5）。

### 5.1 核心八页

| 路径 | 类型 | 内容与 SEO 要点 | 数据来源 | 结构化数据 |
|---|---|---|---|---|
| `/` | 首页 | 今日题目卡片（题号+起始词+步数）、四层提示入口、solver 入口、昨日回顾 | daily JSON | WebApplication + BreadcrumbList |
| `/answer-today/` | 当日答案 | **一屏给完**：起始词→步数→每一行怎么改→复制分享；等长路径数；提示折叠区 | daily JSON | FAQPage + BreadcrumbList |
| `/hints/` | 提示页 | 四层 spoiler-safe 提示逐级揭晓，`#hint-2` 锚点不剧透下层；提示区与答案区物理分离 | daily JSON | BreadcrumbList |
| `/solver/` | 解题器 | 输入任意四字母词，纯前端查预生成 JSON 出路径（不上传、无后端）+ 难度标签 | word CSV | WebApplication + FAQPage |
| `/unlimited/` | 无限模式页 | 规则说明（1,476 题库、四字母、目标 POOP、每步真词、按步数分难度）+ 随机起始词工具 | word CSV | FAQPage |
| `/archive/` | 答案存档 | 按日期/题号分页；1,137 期全部预生成静态化，历史页永不重复生成 | daily_sequence.csv | BreadcrumbList |
| `/from/{word}/` | 长尾矩阵 | 约 2,397 页构建期批量生成，见 5.2 | word CSV | BreadcrumbList |
| `/how-to-play/` | 玩法指南 | 词梯规则、起源（Lewis Carroll 1877 Doublets）、手工解题技巧，400+ 字原创长文 | — | FAQPage |

### 5.2 长尾矩阵 `/from/{word}/`（本站最大的量来自这里）

- **URL 用起始词做键**（`/from/rise/`），**绝不用官方关卡号**——官方题库编号与自有词表对不上，挂「Level #372」而内容不符会被判定错误内容。
- 页面模板：H1 = `{WORD} to POOP in {N} steps`；唯一/全部最短路径；**每一步的其他候选词及为什么不更短**（BFS 前驱数据天然支持，停留时间 >60 秒的关键内容）；难度标签；内链 `/solver/` 与相邻词页形成互链网。
- 难度分档（对齐官方「Medium, 5 steps」口径）：1–3 步 Easy / 4–5 步 Medium / 6 步以上 Hard。
- title 变体轮换：`"{word} to poop"` / `"poop ladder from {word}"` / `"how to get from {word} to poop"`。

### 5.3 二期扩展页（主站稳定后再加）

`/statistics/`（步数分布、极值词——graph_stats.json 现成）、`/patterns/`（一步到 POOP 的 11 词——现成）、`/strategy/`（手工策略长文）、`/data-methodology/`（E-E-A-T）、`/es/`、`/de/`（先预留 hreflang）。

### 5.4 技术与 SEO 基线

- **Astro 静态导出 + Cloudflare Pages**；数据构建与页面构建分离，CSV/JSON 是唯一数据源。
- 性能：单页内联 CSS、零 JS 优先；手机首屏 1 秒内可见答案；solver 页字典按需加载。
- 每页三种结构化数据：`WebApplication`、`FAQPage`、`BreadcrumbList`。
- 每个工具页正文 ≥ 400 字原创；长文页 ≥ 6,000 字符。
- Title/H1 覆盖「poople answer / poople answer today / poople solver / poople unlimited / {word} to poop」词族。
- sitemap、canonical、Core Web Vitals 达标。

## 6. 阶段五：部署、自动化与监控

1. **上线前置（M3，最紧急）**：注册 hintdle.com（`.io`、`.app` 一并拿下做保护）；Astro 项目初始化。
2. **构建流水线**：bundle 缓存版本锁定 → `build_official_graph.py` → 静态数据 → SSG 构建 → 部署。
3. **每日流水线（16:10）**：`fetch_today.py` 下载新 bundle 取题 → 生成 daily JSON → 重建当日页 → 部署 → 健康检查。
4. **上线动作（M6）**：Cloudflare Pages 绑定 hintdle.com → Search Console 提交 sitemap → Rich Results Test 校验结构化数据。
5. **监控**：每日页面关键字断言（题号、起始词、步数）、bundle 可用性、结构化数据校验（Rich Results Test）。
6. **告警与降级**：任一环节失败自动显示「更新中」并通知。
7. **数据更新节奏**：bundle 哈希变化即重跑 `build_official_graph.py` 全量验证（BFS 距离必须与内嵌数据 100% 一致）。

## 7. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 商标/版权投诉 | 站和域名一起丢 | 域名站名零品牌词；不做可玩复刻；只做答案/提示/工具 |

| 多语言扩张摊薄精力 | 主线变慢 | /es/ /de/ 放二期，先做透英文主站 |
