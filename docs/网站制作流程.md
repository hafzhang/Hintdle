# hintdle 网站制作流程

> 目标：做一个 Poople 词梯（Word Ladder）的**提示与答案工具站**，核心产品是分级提示（hint），答案页是副产品。
> 本文档是从 0 到上线的完整执行流程，数据层（阶段一）已在本仓库落地并通过基准验证。

---

## 0. 定位与红线

### 做什么
- 用**公开词表 + 自有 BFS 算法**生产词梯数据，不依赖任何竞品内容。
- 以「四层 spoiler-safe 分级提示」为主产品，对标 poople.org 的提示体验。
- 工具页 + 数据页 + 长文指南组合，吃答案词和工具类搜索流量。

### 明确不做（三条红线）
1. **不爬** poople.org / poopleanswer.com 的答案页——竞品内容且每天变，抄来就是错数据。
2. **不抄**任何站点的英文原文——重复内容没有排名。
3. **不做可玩复刻版**——每天维护交互和统计不划算，且有版权风险；只做答案、提示、工具。

### 参考对象（只学结构，不抓内容）
| 对象 | 学什么 |
|---|---|
| poople.org（第 1 名竞品） | 页面结构、四层提示设计、页表规划 |
| stuckonaword.com（老工具站） | 通配桶 + BFS 算法、三种结构化数据、Data & Methodology 页写法 |
| wordzingo.com（长文范本） | 单页 6,000+ 字符的原创长文结构（起源/规则/技巧/FAQ） |
| poople.io（官方站） | 仅用于读取每日起始词；JS 空壳，普通抓取正文为 0 字符 |

### 2.2 为什么选 SOWPODS 做主体（决定性验证）

竞品 poople.org 公开其图为 **5,395 个四字母词**。对三套词表分别从 POOP 做 BFS：

| 词集 | 词数 | 可达率 | TAXI 最短步数 | TAXI 等长路径数 |
|---|---|---|---|---|
| ENABLE | 3,903 | 97.5% | 6 | **3** ❌ |
| SOWPODS | 5,454 | 98.6% | **6** | **5** ✅ |
| 三表并集 | 5,609 | 98.2% | **6** | **5** ✅ |

竞品 #464 页面明确写着 TAXI「最短 6 步、等长路径 5 条」。**SOWPODS 图与该基准完全一致**，证明竞品词图就是 CSW/SOWPODS 系。因此以 SOWPODS 5,454 词为主体，按常用度裁剪 59 个最低频词到 **5,395**。

### 2.3 裁剪规则（可复现）

1. 必保留集 = Google 万词中的四字母词 ∪ ENABLE 四字母词（常用词与 playable 词不删）。
2. 可删集按词频从低到高排序（wordfreq Zipf 词频优先；未安装时自动降级为 Google 排名分）。
3. 逐词试删，每次删后重跑 BFS，满足全部守卫条件才真删：
   - POOP 可达词数不下降；
   - TAXI 仍为 6 步、5 条最短路径；
   - POOP 的一步邻居数不减少。
4. 删满 59 个即停止，最终词数 = 5,395。

### 2.4 算法（与 stuckonaword.com 公开思路一致）

- **建图**：通配桶。每个词的每个位置替换为 `*` 作为桶 key（`T*XI`、`TA*I`…），同桶词互为一步邻居。
- **求解**：从 POOP 做 BFS，记录每个词的距离、首个前驱、最短路径数量。
- **回溯**：沿前驱链得到一条已验证最短路径；在最短路径 DAG 上 DFS 可枚举全部等长路径。

复现命令：

```powershell
python scripts/build_word_graph.py     # 构建 5,395 词图并输出全部数据
python scripts/hint_engine.py taxi     # 查看 TAXI 的四层提示与完整路径
python scripts/hint_engine.py taxi --json
```

### 2.5 数据产物（`data/processed/`）

| 文件 | 内容 | 消费页面 |
|---|---|---|
| `word_ladder_4letter.csv` | 每词：距离、前驱、最短路径数、是否可达、词频、来源标记 | 全站数据源 |
| `poop_neighbors.json` | 一步到 POOP 的词与通配模式 | `/word-ladder-patterns/` |
| `taxi_shortest_paths.json` | TAXI→POOP 全部 5 条最短路径（基准样例） | 答案页/测试夹具 |
| `graph_stats.json` | 距离分布、极值词、不可达词、验证结果 | `/word-ladder-statistics/`、Data & Methodology |

### 2.6 验收标准（阶段一）

- [x] 词数 = 5,395
- [x] TAXI 距离 = 6、最短路径数 = 5
- [x] 规范路径 = TAXI→TALI→TALL→TOLL→TOOL→POOL→POOP
- [x] 可达率 ≥ 98%，不可达词有显式清单（页面不展示不可达答案）
- [x] 全流程零抓取、零猜测，输入仅公开词表

## 3. 阶段二：每日题目获取（最高风险点）

### 3.1 事实
- 官方 poople.io 是 JS 空壳，普通 HTTP 抓取正文 **0 字符**，起始词必须用无头浏览器执行 JS 后读取。
- 官方每天 **08:00 UTC（北京时间 16:00）** 换题。

### 3.2 实现方案
1. Playwright（Python 版）定时访问 poople.io，等待游戏组件渲染后读取当日起始词与题号。
2. 调度时间定在**北京时间 16:10**（留 10 分钟缓冲），用系统计划任务或 CI cron。
3. 读到起始词后立即调用本地 `hint_engine.build_hints()` 生成当日数据，落库为静态 JSON：`data/daily/YYYY-MM-DD.json`。
4. 前端只读取本地静态 JSON，**运行时不依赖官方站**。

### 3.3 降级方案（必须做）
- 连续 3 次读取失败 / 页面结构改版 / 起始词不在本地词图中：不输出猜测数据。
. 页面显示「今日题目更新中（Updating today's puzzle）」，保留昨日归档可访问。
- 发送告警（日志/邮件/webhook 任选），人工介入。
- 铁律：**错数据比不更新更伤**，宁可不更新也不能输出错误起始词。

### 3.4 验收
- [ ] 无头浏览器能稳定读到题号 + 起始词（连续 7 天演练）
- [ ] 起始词必在本地 5,395 词图内，否则触发降级
- [ ] 断网/改版演练时页面正确显示更新中状态

## 4. 阶段三：提示引擎（核心产品，脚本已就绪）

四层提示由弱到强，与竞品验证过的设计一致（`scripts/hint_engine.py`）：

| 层级 | 内容 | TAXI 示例 |
|---|---|---|
| Hint 1 | 最优路径共几步 | 最短 6 步 |
| Hint 2 | 第一步改动第几位 | 第 3 位（X） |
| Hint 3 | 该位字母变化 | X → L |
| Hint 4 | 第一步完整单词 | TAXI → TALI |
| 揭晓 | 完整最短路径 + 等长路径数 | 5 条，默认展示 1 条 |

交互要求：每层提示默认折叠、点击逐级展开，URL 带 `#hint-2` 锚点且不剧透下层内容；答案区与提示区物理分离。

## 5. 阶段四：页面工程（11 页 + 2 语言版）

### 5.1 页表（在原 8 页基础上补 3 个数据页）

| 路径 | 类型 | 要点 |
|---|---|---|
| `/` | 首页 | 今日题目卡片 + 四层提示入口 + 工具导航 |
| `/answers/today/` | 当日答案 | 提示折叠、路径揭晓、结构化 FAQ |
| `/answers/` | 答案存档 | 按日期/题号分页，静态化 |
| `/poople-solver/` | 解题器 | 输入任意四字母词，实时出路径（CSV 本地查，无需后端） |
| `/word-ladder-statistics/` | **数据页（新增）** | 步数分布、最长最短词，数据来自 graph_stats.json |
| `/word-ladder-patterns/` | **数据页（新增，高价值）** | 哪些词一步到 POOP，poop_neighbors.json |
| `/word-ladder-strategy/` | **指南页（新增）** | 手工解题策略，400+ 字原创 |
| `/word-ladder-faq/`（或 `/faq/`） | FAQ | FAQPage 结构化数据 |
| `/data-methodology/` | 方法论 | 公开词表 + BFS 说明，建立 E-E-A-T |
| `/word-ladder-guide/`（长文） | 长文 | 仿 wordzingo 结构：起源（Lewis Carroll 1877 Doublets）→规则→技巧→词长举例→教学用途→FAQ |
| 归档/标签等支撑页 | SEO | 面包屑 BreadcrumbList |
| `/es/`、`/de/` | 多语言 | 竞品已验证有搜索量，二期再做，先预留 hreflang |

### 5.2 技术与 SEO 基线
- 静态站点生成（任意 SSG），数据构建与页面构建分离；CSV/JSON 是唯一数据源。
- 每页三种结构化数据照 stuckonaword 配齐：`WebApplication`、`FAQPage`、`BreadcrumbList`。
- 每个工具/数据页正文 ≥ 400 字原创；长文页 ≥ 6,000 字符。
- Title/H1/内联锚文本覆盖「poople answer / word ladder solver / 4 letter word ladder」等词族。
- sitemap、canonical、hreflang、Core Web Vitals 达标；字典数据按需加载（参考竞品）。

## 6. 阶段五：部署、自动化与监控

1. **构建流水线**：公开词表版本锁定（记录 commit/下载日期）→ `build_word_graph.py` → 静态数据 → SSG 构建 → 部署。
2. **每日流水线（16:10）**：Playwright 取题 → 提示引擎生成 JSON → 重建当日页 → 部署 → 健康检查。
3. **监控**：每日页面关键字断言（题号、起始词、步数）、抓取可用性、结构化数据校验（Rich Results Test）。
4. **告警与降级**：任一环节失败自动显示「更新中」并通知。
5. **数据更新节奏**：词表每季度复核一次；SOWPODS 新版发布时重跑基准验证（TAXI 6/5 必须保持）。

## 7. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 无头浏览器被封/官方改版 | 每日更新中断 | 降级页 + 告警 + 人工补录；不输出猜测数据 |
| 竞品词表版本与 SOWPODS 有出入 | 个别词路径不一致 | 基准守卫 + 每季度复核；以自有词表为唯一事实源并在方法论页声明 |
| 行业竞争加速（poopleanswer.com 已环比 -12.5%） | 流量窗口收窄 | 差异化只押体验与提示，不拼页面数量；长文与数据页建壁垒 |
| 多语言扩张摊薄精力 | 主线变慢 | /es/ /de/ 放二期，先做透英文主站 |
